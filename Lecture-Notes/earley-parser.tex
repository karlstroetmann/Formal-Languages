\noindent
In this chapter we will discuss an efficient algorithm that takes two inputs:
\begin{enumerate}
\item A context-free grammar $G = \langle V, \Sigma, R, s \rangle$ and
\item a string $w \in \Sigma^*$.
\end{enumerate}
The algorithm decides whether $w \in L(G)$ holds, i.e.~it checks whether the string is a
member of the language generated by the \simtextsc{Cfg} $G$.

The algorithm that is presented next was published in 1970 by Jay Earley \cite{earley:70}.
There is another algorithm solving the same problem, namely the
\href{https://en.wikipedia.org/wiki/CYK_algorithm}{Cocke-Younger-Kasami algorithm},
\index{Cocke-Younger-Kasami algorithm}
  which is also known as the
\blue{\simtextsc{Cyk} algorithm}.\index{CYK algorithm@\simtextsc{Cyk} algorithm}
It was discovered independently by John Cocke
\cite{cocke:1970}, Daniel H.~Younger \cite{younger:1967}, and Tadao Kasami \cite{kasami:1965}.
The \simtextsc{Cyk} algorithm can only be used when the grammar is in
\href{https://en.wikipedia.org/wiki/Chomsky_normal_form}{Chomsky normal form}.
Although every context-free grammar can be transformed into Chomsky normal form automatically, the resulting
grammar is often considerably larger, and the parse trees refer to the transformed grammar instead of the original
one.  Furthermore, the \simtextsc{Cyk} algorithm always has the complexity $\mathcal{O}(n^3)$, which is
prohibitive for practical applications.

In contrast, Earley's algorithm works for arbitrary context-free grammars.  In the general case, it has a
complexity of $\mathcal{O}(n^3)$ where $n$ is the length of the string that is to be parsed.  However, if the
grammar is not ambiguous, the complexity is only $\mathcal{O}(n^2)$.  With an improvement due to Joop Leo
\cite{leo:1991}, Earley's algorithm even runs in linear time for all LR($k$) grammars, and hence also for all
LL($k$) grammars.  The implementation presented in this chapter does not contain this improvement.  We will
discuss LR(1) grammars in Chapter \ref{chapter:bottom-up}.

This chapter is structured as follows:
\begin{enumerate}[(a)]
\item First, we sketch the theory of Earley's algorithm.
\item Next, we show how this algorithm can be implemented in \textsl{Python}.
\end{enumerate}

\section{The Earley Algorithm}
The central notion that is needed to understand Earley's algorithm is the notion of an
\blue{Earley object}\index{Earley object}\glsadd{earleyobj}\index{Earley's algorithm}.  This notion is defined below.

\begin{Definition}[Earley Object]
  Assume that  $G = \langle V, \Sigma, R, s \rangle$ is a context-free grammar and
  $w = x_1x_2 \cdots x_n \in \Sigma^*$ is a string of length $n$.  A pair of the form
  \\[0.2cm]
  \hspace*{1.3cm}
  $\langle a \rightarrow \beta \bullet \gamma, k \rangle$
  \\[0.2cm]
  is called an \blue{Earley object} if and only if
  \begin{enumerate}[(a)]
  \item $(a \rightarrow \beta\gamma) \in R$ \quad and
  \item $k \in \{0,1,\cdots,n\}$. \eox
  \end{enumerate}
\end{Definition}

\noindent
In the literature, Earley objects are also called \blue{Earley items}.\index{Earley item|see{Earley object}}

\noindent
\textbf{Explanation}:
An Earley object describes a possible state of a parser.
If a parser has to parse a string of the form $x_1 \cdots x_n$, then this parser will maintain
$n+1$ sets of Earley objects.  These sets are denoted as
\\[0.2cm]
\hspace*{1.3cm}
$Q_0, Q_1, \cdots, Q_n$.
\\[0.2cm]
If $i \in \{0,1, \cdots, n\}$, then the set $Q_i$ contains those Earley objects that describe the state of
the parser after it has parsed the tokens $x_1$, $\cdots$, $x_i$.  
The interpretation of 
\\[0.2cm]
\hspace*{1.3cm}
$\langle a \rightarrow \beta \bullet \gamma, k \rangle \in Q_j$ \quad where  $j \geq k$
\\[0.2cm]
is as follows:
\begin{enumerate}
\item The parser tries to use the grammar rule $a \rightarrow \beta \gamma$ to parse the variable $a$ at the
      beginning of the substring $x_{k+1} \cdots x_n$.
\item The parser has already parsed $\beta$ in the substring  $x_{k+1} \cdots x_j$, i.e.~we have
      \\[0.2cm]
      \hspace*{1.3cm}
      $\beta \Rightarrow^* x_{k+1} \cdots x_j$.
\item Hence, in order to parse the variable $a$ the parser only needs to recognize $\gamma$ at the beginning of
      the substring $x_{j+1} \cdots x_n$.
\end{enumerate}
Earley's  algorithm manages the sets $Q_0$, $Q_1$, $\cdots$, $Q_n$  of Earley objects.  The set $Q_j$ describes
all states the parser could be in after it has read the prefix $x_1 \cdots x_j$.

At the beginning of the algorithm we add a new start variable  $\widehat{s}$\glsadd{newstart} to the grammar.  Furthermore the
rule $\widehat{s} \rightarrow s$ is added to the grammar.  Hence, the grammar $G = \langle V, \Sigma, R, s \rangle$
is transformed into the \blue{augmented grammar}\index{augmented grammar}
\\[0.2cm]
\hspace*{1.3cm}
$\widehat{G} = \langle V \cup \{\widehat{s}\}, \Sigma, R \cup \{ \widehat{s} \rightarrow s \}, \widehat{s} \,\rangle$. 
\\[0.2cm]
Next, the set $Q_0$ is defined as
\\[0.2cm]
\hspace*{1.3cm}
$Q_0 := \bigl\{ \pair(\widehat{s} \rightarrow \bullet s, 0) \bigr\}$.
\\[0.2cm]
The reason is that the  parser should recognize the start symbol $s$ at the beginning of the string $x_1 \cdots
x_n$.
The remaining sets  $Q_j$ are initially empty for $j=1,\cdots,n$.  These sets are extended by the
following three operations: 
\begin{enumerate}
\item \emph{Scanning}\index{Earley's algorithm!scanning}

      If the set $Q_j$ contains an Earley object of the form 
      $\pair(a \rightarrow \beta \bullet T \gamma, k)$ and $T$ is a 
      terminal, then the parser tries to parse the right hand side of the grammar rule
      $a \rightarrow \beta T \gamma$ and, after reading $x_{k+1} \cdots x_j$, it has already recognized $\beta$.
      If this $\beta$ is now followed by the token $T$, then in order to recognize $a$ with the grammar rule
      $a \rightarrow \beta T \gamma$, the parser only has to recognize $\gamma$ in the substring
      $x_{j+2} \cdots x_n$.  Hence, in this case we add the Earley object
      \\[0.2cm]
      \hspace*{1.3cm}
      $\pair(a \rightarrow \beta T \bullet \gamma, k)$
      \\[0.2cm]
      to the set $Q_{j+1}$:
      \\[0.2cm]
      \hspace*{1.3cm}
      $\pair(a \rightarrow \beta \bullet T \gamma, k) \in Q_j \wedge x_{j+1} = T
       \;\Rightarrow\;
       Q_{j+1} := Q_{j+1} \cup \bigl\{ \pair(a \rightarrow \beta T \bullet \gamma, k) \bigr\}$.
      \\[0.2cm]
      This operation is also called \emph{reading}, since it reads the next token.
\item \emph{Prediction}\index{Earley's algorithm!prediction}

      If the set $Q_j$ contains an Earley object of the form $\pair(a \rightarrow \beta \bullet c \delta, k)$
      such that $c$ is a variable, then the parser tries to recognize $c\delta$ after having
      parsed the substring $x_{k+1} \cdots x_j$ as $\beta$.  Hence the parser now has to recognize the variable
      $c$.  Therefore, for every rule of the form $c \rightarrow \gamma$ that is contained in the grammar $G$
      the Earley object 
      $\pair(c \rightarrow \bullet \gamma, j)$ is added to the set $Q_j$:
      \\[0.2cm]
      \hspace*{1.3cm}
      $\pair(a \rightarrow \beta \bullet c \delta, k) \in Q_j 
       \wedge (c \rightarrow \gamma) \in R 
       \;\Rightarrow\;
       Q_j := Q_j \cup\bigl\{ \pair(c \rightarrow \bullet\gamma, j)\bigr\}$.
\item \emph{Completion}\index{Earley's algorithm!completion}

      If the set $Q_i$ contains an Earley object of the form $\pair(c \rightarrow \gamma \bullet, j)$
      and the set $Q_j$ contains an Earley object of the form 
      $\pair(a \rightarrow \beta \bullet c \delta,k)$, then the parser has tried to parse the variable $c$
      after it had read the substring $x_1\cdots x_{j}$ and after reading the substring $x_{j+1}\cdots x_i$
      it has recognized the variable $c$.
      Therefore, the Earley object
      $\pair(a \rightarrow \beta c \bullet \delta,k)$
      is now added to the set $Q_i$:
      \\[0.2cm]
      \hspace*{1.3cm}
      $\pair(c \rightarrow \gamma \bullet, j) \in Q_i \wedge
       \pair(a \rightarrow \beta \bullet c \delta,k) \in Q_j \;\Rightarrow\;
       Q_i := Q_i \cup \bigl\{ \pair(a \rightarrow \beta c \bullet \delta,k) \bigr\}
      $.
\end{enumerate}
When trying to parse the string $w = x_1 \cdots x_n$ with the grammar
$G = \langle V, \Sigma, R, s \rangle$ Earley's algorithm works as follows:
\begin{enumerate}
\item The sets  $Q_i$ are initialized as follows:
      \\[0.2cm]
      \hspace*{1.3cm}
      $Q_0 := \bigl\{ \pair(\widehat{s} \rightarrow \bullet s, 0) \bigr\}$,
      \\[0.2cm]
      \hspace*{1.3cm}
      $Q_i := \bigl\{ \bigr\}$ \quad for $i=1,\cdots,n$.
\item After that we iterate from $i=0$ to $i=n$ and perform the following operations:
      \begin{enumerate}[(a)]
      \item The set $Q_i$ is enlarged using completion until we find no further
            Earley objects.
      \item Next we use prediction to enlarge the set $Q_i$.
            Again, this operation is performed until no new Earley objects are found.
      \item If $i < n$, we read the next token and use it to initialize $Q_{i+1}$.
      \end{enumerate}
      If the grammar $G$ has  $\lambda$-rules, i.e.~if it has rules with empty right hand side of the form
      \\[0.2cm]
      \hspace*{1.3cm}
      $c \rightarrow \lambda$,
      \\[0.2cm]
      then it might happen that after applying prediction in the set $Q_i$, we can immediately apply
      completion in $Q_i$ again.  In this case prediction and completion have to be iterated until no further Earley
      objects are generated for $Q_i$.
\item If after termination of the algorithm the set  $Q_n$ contains the Earley object
      $\pair(\widehat{s} \rightarrow s \bullet,0)$, then parsing is successful and we have shown that
      the string $w = x_1 \cdots x_n$ is an element of $L(G)$.
\end{enumerate}

 $\Sigma = \{ \squoted{1}, \squoted{2}, \squoted{3}, \squoted{+}, \squoted{*} \}$.
\\[0.2cm]
We demonstrate how the string “\texttt{1+2*3}” can be parsed using this grammar and Earley’s algorithm. In the
following representation, we will abbreviate the syntactic variable \texttt{expr} with the letter $e$, write 
$p$ for \texttt{prod}, and use $f$ as an abbreviation for \texttt{fact}.

\begin{enumerate}
\item We initialize $Q_0$ as
      \\[0.2cm]
      \hspace*{1.3cm}
      $Q_0 = \{ \pair(\widehat{s} \rightarrow \bullet\, e, 0) \}$. 
      \\[0.2cm]
      The sets $Q_1$, $Q_2$, $Q_3$, $Q_4$ and $Q_5$ are initially empty. If we apply the completion operation
      to the set $Q_0$, we find no new Earley objects.

      Next, we apply the prediction operation to the Earley object  
      $\pair(\widehat{s} \rightarrow \bullet\, e, 0)$. This initially adds the following two Earley objects to
      the set $Q_0$: 
      \[
        \pair(e \rightarrow \bullet\, e\, \squoted{+}\, p, 0) 
        \quad \text{and} \quad 
        \pair(e \rightarrow \bullet\, p, 0)
      \]  
      We can apply the prediction operation once more to the Earley object $\pair(e \rightarrow \bullet\, p, 0)$,
      which results in two new Earley objects:   
      \[
        \pair(p \rightarrow \bullet\, p\, \squoted{*}\, f, 0) 
        \quad \text{and} \quad 
        \pair(p \rightarrow \bullet\, f, 0)
      \]  
      Applying the prediction operation to the Earley object $\pair(p \rightarrow \bullet\, f, 0)$, we finally
      add the following Earley objects to $Q_0$:   
      \[
        \pair(f \rightarrow \bullet\, \squoted{1}, 0), \quad 
        \pair(f \rightarrow \bullet\, \squoted{2}, 0), \quad \text{and} \quad 
        \pair(f \rightarrow \bullet\, \squoted{3}, 0)
      \]  
      In total, $Q_0$ now contains the following Earley objects:  
      \begin{enumerate}
      \item $\pair(\widehat{s} \rightarrow \bullet\, e, 0)$,
      \item $\pair(e \rightarrow \bullet\, e\, \squoted{+}\, p, 0)$,
      \item $\pair(e \rightarrow \bullet\, p, 0)$,
      \item $\pair(p \rightarrow \bullet\, p\, \squoted{*}\, f, 0)$,
      \item $\pair(p \rightarrow \bullet\, f, 0)$,
      \item $\pair(f \rightarrow \bullet\, \squoted{1}, 0)$,
      \item $\pair(f \rightarrow \bullet\, \squoted{2}, 0)$,
      \item $\pair(f \rightarrow \bullet\, \squoted{3}, 0)$.
      \end{enumerate}
      Next, we apply the scanning operation to $Q_0$. Since the first character of the string to be parsed is
      “1”, the set $Q_1$ takes the following form:   
      \[
        Q_1 = \bigl\{ \pair(f \rightarrow \squoted{1}\, \bullet, 0) \bigr\}
      \]
\item Now, we set $i = 1$ and first apply the completion operation to $Q_1$. Based on the Earley object
      $\pair(f \rightarrow \squoted{1}\, \bullet, 0)$ in $Q_1$, we look for an Earley object in $Q_0$ where the marker
      “$\bullet$” is positioned before the variable $f$. We find the Earley object
       $\pair(p \rightarrow \bullet\, f, 0)$. Therefore, we add the following Earley object to $Q_1$:   
       \[
         \pair(p \rightarrow f\, \bullet, 0)
       \]  
       We can then apply the completion operation again. After repeated applications, $Q_1$ contains the
       following Earley objects:
       \begin{enumerate}
       \item $\pair(f \rightarrow \squoted{1}\, \bullet, 0)$,
       \item $\pair(p \rightarrow f\, \bullet, 0)$,
       \item $\pair(p \rightarrow p \bullet \squoted{*}\, f, 0)$, 
       \item $\pair(e \rightarrow p\, \bullet, 0)$,
       \item $\pair(e \rightarrow e \bullet \squoted{+}\, p, 0)$,
       \item $\pair(\widehat{s} \rightarrow e\, \bullet, 0)$.
       \end{enumerate}  
       Next, we apply the prediction operation to these Earley objects. However, since the marker “$\bullet$” in
       none of the Earley objects in $Q_1$ precedes a variable, no new Earley objects are generated.   

       Finally, we apply the scanning operation to $Q_1$. Since the character “\texttt{+}” is at position 2 in
       the string “\texttt{1+2*3}” and $Q_1$ contains the Earley object   
       \[
         \pair(e \rightarrow e \bullet \squoted{+}\, p, 0),
       \]  
       we add the following Earley object to $Q_2$:  
       \[
         \pair(e \rightarrow e\, \squoted{+} \bullet p, 0)
       \]  
\item Next, we set $i = 2$ and first apply the completion operation to $Q_2$. At this point, we have  
      \[
        Q_2 = \{ \pair(e \rightarrow e\, \squoted{+} \bullet p, 0) \}.
      \]  
      Since the marker “$\bullet$” in the only Earley object present here is not at the end of the grammar rule,
      the completion operation does not yield any new Earley objects in this step.   

      Next, we apply the prediction operation to $Q_2$. Since the marker precedes the variable $p$, we first
      find the following two Earley objects:   
      \[
        \pair(p \rightarrow \bullet\, f, 2) \quad \text{and} \quad \pair(p \rightarrow \bullet\, p\, \squoted{*}\, f, 2).
      \]  
      Since in the first Earley object the marker precedes the variable $f$, the prediction operation can be
      applied once more, yielding the following additional Earley objects:   
      \begin{enumerate}
      \item $\pair(f \rightarrow \bullet\, \squoted{1}, 2)$, 
      \item $\pair(f \rightarrow \bullet\, \squoted{2}, 2)$,
      \item $\pair(f \rightarrow \bullet\, \squoted{3}, 2)$.
      \end{enumerate}  
      Finally, we apply the scanning operation to $Q_2$. Since the third character of the string
      “\texttt{1+2*3}” is the digit “2”, $Q_3$ now takes the form   
      \[
        Q_3 = \{ \pair(f \rightarrow \squoted{2}\, \bullet, 2) \}.
      \]
\item We set $i = 3$ and apply the completion operation to $Q_3$. This adds  
      \[
        \pair(p \rightarrow f\, \bullet, 2)
      \]  
      to $Q_3$. Here, we can apply the completion operation once more. Through iterative application of the
      completion operation, we additionally obtain the following Earley objects:   
      \begin{enumerate}
      \item $\pair(p \rightarrow p \bullet \squoted{*}\, f, 2)$,
      \item $\pair(e \rightarrow e\, \squoted{+}\, p\, \bullet, 0)$,
      \item $\pair(e \rightarrow e \bullet \squoted{+}\, p, 0)$,
      \item $\pair(\widehat{s} \rightarrow e\, \bullet, 0)$.
      \end{enumerate}  
      Finally, we apply the scanning operation. Since the next character to be read is the symbol “\texttt{*}”,
      we get   
      \[
        Q_4 = \{ \pair(p \rightarrow p\, \squoted{*} \bullet f, 2) \}.
      \] 
\item We set $i = 4$. The completion operation does not yield any new Earley objects. The prediction operation
      provides the following Earley objects:   
      \begin{enumerate}
      \item $\pair(f \rightarrow \bullet\, \squoted{1}, 4)$, 
      \item $\pair(f \rightarrow \bullet\, \squoted{2}, 4)$,
      \item $\pair(f \rightarrow \bullet\, \squoted{3}, 4)$.
      \end{enumerate}  
      Since the next character is the digit “3”, the scanning operation for $Q_5$ results in:  
      \[
        Q_5 = \{ \pair(f \rightarrow \squoted{3}\, \bullet, 4) \}.
      \]
\item We set $i = 5$. The completion operation sequentially provides the following Earley objects:
      \begin{enumerate}
      \item $\pair(p \rightarrow p\, \squoted{*}\, f\, \bullet, 2)$,
      \item $\pair(e \rightarrow e\, \squoted{+}\, p\, \bullet, 0)$,
      \item $\pair(p \rightarrow p \bullet \squoted{*}\, f, 2)$,
      \item $\pair(e \rightarrow e \bullet \squoted{+}\, p, 0)$,
      \item $\pair(\widehat{s} \rightarrow e\, \bullet, 0)$.
      \end{enumerate}
\end{enumerate}
Since the set $Q_5$ contains the Earley object $\pair(\widehat{s} \rightarrow e\, \bullet, 0)$, we can conclude
that the string “\texttt{1+2*3}” indeed belongs to the language generated by the given grammar.

\noindent
\textbf{Remark}: Strictly speaking, the algorithm presented in this chapter is a
\blue{recognizer}\index{recognizer} and not a parser:  It decides whether $w \in L(G)$, but it does not compute a
parse tree.  In order to construct a parse tree, every Earley object that is created by scanning or completion has
to remember the Earley objects from which it has been created.  Starting with the Earley object
$\pair(\widehat{s} \rightarrow s \bullet, 0) \in Q_n$, these references can then be followed backwards to build the
parse tree.  If the grammar is ambiguous, an Earley object can be created in several ways, and then the string has
several parse trees.  The notebook \texttt{02-Earley-Parser-Chatty}, which is presented in the next section,
implements this idea and computes all parse trees of a string.

\\[0.2cm]
contains an implementation of Earley's algorithm.  The notebook
\\[0.2cm]
\hspace*{1.3cm}
\href{https://github.com/karlstroetmann/Formal-Languages/blob/master/Python/Chapter-09/02-Earley-Parser-Chatty.ipynb}{Python/Chapter-09/02-Earley-Parser-Chatty.ipynb}
\\[0.2cm]
implements the same algorithm, but in addition it shows how the parser proceeds:  It prints every Earley object
that is added by the completion, prediction, or scanning operation, and after every token it prints the sets $Q_i$
and $Q_{i+1}$.  Furthermore, it remembers for every Earley object all the ways in which it has been created.  If
parsing is successful, it uses this information to compute all parse trees of the input and draws them with
\textsl{Graphviz}.

In the rest of this section we discuss the implementation of Earley's algorithm line by line.  To keep the
listings short, they show a simplified version of the code in the notebook \texttt{01-Earley-Parser}:  We have
removed the type annotations and the declarations that are only needed by the type checker.

The implementation expects its input in the following form:
\begin{enumerate}
\item A grammar is represented as a list of rules.  A rule $a \rightarrow X_1 \cdots X_n$ is represented as the list
      \\[0.2cm]
      \hspace*{1.3cm}
      \texttt{[}$a$\texttt{,} $X_1$\texttt{,} $\cdots$\texttt{,} $X_n$\texttt{]}
      \\[0.2cm]
      of strings.  The names of syntactical variables start with a lower case letter.  A token is either a name that
      starts with an upper case letter, like \texttt{NUMBER}, or a literal.  Literals keep their double quotes,
      i.e.~the literal \squoted{+} is represented by a string of three characters that starts and ends with a double
      quote.  Therefore, a literal can never be confused with a variable.
\item The string that is to be parsed is represented as a list of tokens.  For example, the string
      ``\texttt{1+2*3}'' is represented as the list
      \\[0.2cm]
      \hspace*{1.3cm}
      \texttt{['NUMBER', '"+"', 'NUMBER', '"*"', 'NUMBER']}.
\end{enumerate}
The notebook creates these lists with the help of a parser generated by \simtextsc{Larkita} and a small scanner.
We do not discuss these parts here, since they are not part of Earley's algorithm.

In the notebook, every method is defined in a cell of its own.  Therefore, most methods are first defined as
functions and then attached to their class with two lines of the form
\\[0.2cm]
\hspace*{1.3cm}
\texttt{EarleyObject.isComplete = isComplete}
\\[0.1cm]
\hspace*{1.3cm}
\texttt{del isComplete}
\\[0.2cm]
The first of these lines makes the function a method of the class and the second line removes the global name of
the function.  As these lines always have the same form, we will not mention them again.

\subsection{The Class \texttt{EarleyObject}}
The class \texttt{EarleyObject} represents a single Earley object.  As the names of the member variables of this
class refer to the letters $\alpha$ and $\beta$, we write an Earley object in this subsection in the form
\\[0.2cm]
\hspace*{1.3cm}
$\pair(a \rightarrow \alpha \bullet \beta, k)$.

\begin{figure}[!ht]
\centering
\begin{minted}[ frame         = lines,
                framesep      = 0.3cm,
                firstnumber   = 1,
                bgcolor       = sepia,
                numbers       = left,
                numbersep     = 0.3cm,
                xleftmargin   = 0.5cm,
                xrightmargin  = 0.5cm,
                gobble        = 4,
              ]{python3}
    class EarleyObject():
        def __init__(self, variable, alpha, beta, index):
            self.mVariable = variable
            self.mAlpha    = alpha
            self.mBeta     = beta
            self.mIndex    = index

        def __eq__(self, other):
            return isinstance(other, EarleyObject)   and \
                   self.mVariable == other.mVariable and \
                   self.mAlpha    == other.mAlpha    and \
                   self.mBeta     == other.mBeta     and \
                   self.mIndex    == other.mIndex

        def __hash__(self):
            return hash(self.__repr__())

        def __repr__(self):
            rhs = ' '.join(self.mAlpha + ('•',) + self.mBeta)
            return f'<{self.mVariable} → {rhs}, {self.mIndex}>'
\end{minted}

\begin{enumerate}
\item Line 2 -- 6 define the constructor.  It stores the components of the Earley object
      $\pair(a \rightarrow \alpha \bullet \beta, k)$ in four member variables:
      \begin{enumerate}[(a)]
      \item \texttt{mVariable} stores the variable $a$,
      \item \texttt{mAlpha} stores the symbols of $\alpha$ as a tuple of strings,
      \item \texttt{mBeta} stores the symbols of $\beta$ as a tuple of strings, and
      \item \texttt{mIndex} stores the number $k$.
      \end{enumerate}
\item Line 8 -- 13 define the method \texttt{\_\_eq\_\_}.  Two Earley objects are equal if and only if they agree in
      all four components.  \textsl{Python} derives the operator \texttt{!=} from the method \texttt{\_\_eq\_\_}, so
      \texttt{\_\_ne\_\_} need not be defined.
\item Line 15 -- 16 define the method \texttt{\_\_hash\_\_}.  We need this method because Earley's algorithm stores
      Earley objects in sets and \textsl{Python} requires the elements of a set to have a hash value.
      The hash value of an Earley object is computed by converting the object into a string and taking the hash
      value of this string.  Equal Earley objects are converted into equal strings and therefore get equal hash
      values.
\item Line 18 -- 20 define the method \texttt{\_\_repr\_\_}, which converts an Earley object into a string.
      Line 19 joins the symbols of $\alpha$, the marker ``$\bullet$'', and the symbols of $\beta$, separated by
      blanks.  Line 20 then builds the string that represents the Earley object.  For example, the Earley object
      $\pair(\textsl{expr} \rightarrow \textsl{expr} \quoted{+} \bullet\; \textsl{prod}, 0)$
      is converted into the string
      \\[0.2cm]
      \hspace*{1.3cm}
      \texttt{<expr → expr "+" • prod, 0>}.
\end{enumerate}

      \item If the marker is not at the end of the rule, line 21 sets \texttt{var} to the symbol following the

      \item In all other cases, line 24 returns \texttt{None}.
      \end{enumerate}

      To this end, line 31 appends the first element of \texttt{mBeta} to \texttt{mAlpha} and line 32
      removes this element from \texttt{mBeta}.  The original Earley object is not changed.
\end{enumerate}

\subsection{The Class \texttt{EarleyParser}}
The class \texttt{EarleyParser} implements Earley's algorithm.  Figure
\ref{fig:01-Earley-Parser.ipynb:EarleyParser} on page \pageref{fig:01-Earley-Parser.ipynb:EarleyParser}
shows its constructor and the method \texttt{parse}, which controls the algorithm.

\begin{figure}[!ht]
\centering
\begin{minted}[ frame         = lines,
                framesep      = 0.3cm,
                firstnumber   = 1,
                bgcolor       = sepia,
                numbers       = left,
                numbersep     = 0.3cm,
                xleftmargin   = 0.5cm,
                xrightmargin  = 0.5cm,
                gobble        = 4,
              ]{python3}
    class EarleyParser():
        def __init__(self, grammar, TokenList):
            self.mGrammar   = grammar
            self.mString    = [None] + TokenList
            self.mStateList = [set() for _ in range(len(TokenList)+1)]
            self.mStateList[0] = { self.mGrammar.startObject() }

    def earley_parse(self):
        "run Earley's algorithm"
        n = len(self.mString) - 1 # mString[0] = None
        for i in range(0, n+1):
            change = True
            while change:
                change = self.complete(i)
                change = self.predict(i) or change
            self.scan(i)
        if self.mGrammar.finishObject() in self.mStateList[-1]:
            print('Parsing successful!')
        else:
            print('Parsing failed!')

    EarleyParser.parse = earley_parse
    del earley_parse
\end{minted}
\vspace*{-0.3cm}
\caption{The constructor of the class \texttt{EarleyParser} and the method \texttt{parse}.}
\label{fig:01-Earley-Parser.ipynb:EarleyParser}
\end{figure}

\begin{enumerate}
\item Line 2 -- 6 define the constructor.  Its arguments are the grammar and the list of tokens that is to be
      parsed.
      \begin{enumerate}[(a)]
      \item Line 3 stores the grammar in the member variable \texttt{mGrammar}.
      \item Line 4 stores the tokens in the member variable \texttt{mString}.  In the description of the algorithm,
            the tokens of the string $w = x_1 \cdots x_n$ are numbered starting with 1, while the indices of a
            \textsl{Python} list start with 0.  Therefore, the value \texttt{None} is put in front of the list of
            tokens.  Then \texttt{mString[$i$]} is the token $x_i$ for all $i \in \{1, \cdots, n\}$.
      \item Line 5 creates the list \texttt{mStateList} of the $n+1$ sets $Q_0$, $Q_1$, $\cdots$, $Q_n$, which are
            all empty at this point.  The set $Q_i$ is stored in \texttt{mStateList[$i$]}.
      \item Line 6 initializes $Q_0$ as the set $\bigl\{ \pair(\widehat{s} \rightarrow \bullet\, s, 0) \bigr\}$.
      \end{enumerate}
\item Line 8 -- 20 define the function \texttt{earley\_parse}, which is attached to the class as the method
      \texttt{parse} in line 22.
      \begin{enumerate}[(a)]
      \item Line 10 computes the number $n$ of tokens.  The value \texttt{None} at the beginning of
            \texttt{mString} must not be counted.
      \item The \texttt{for} loop in line 11 -- 16 processes the sets $Q_0$, $Q_1$, $\cdots$, $Q_n$ in this order.
      \item The \texttt{while} loop in line 13 -- 15 applies the completion operation and the prediction
            operation to the set $Q_i$ until neither of these operations finds a new Earley object.  Both methods
            return \texttt{True} if and only if they have added an Earley object to $Q_i$.  As explained above,
            this repetition is only necessary if the grammar has $\lambda$-rules.

            In line 15, the call of the method \texttt{predict} has to be the first operand of the operator
            \texttt{or}.  As this operator does not evaluate its second operand if the first operand is true, the
            method would otherwise be skipped whenever \texttt{change} is \texttt{True}.
      \item Line 16 applies the scanning operation, which initializes the set $Q_{i+1}$.
      \item After the \texttt{for} loop has finished, line 17 checks whether the set $Q_n$, which is the last
            element of the list \texttt{mStateList}, contains the Earley object
            $\pair(\widehat{s} \rightarrow s\, \bullet, 0)$.  Line 18 and line 20 print the result.
      \end{enumerate}
\end{enumerate}

\centering

    def complete(self, i):
        change = False
        added  = True
        Qi     = self.mStateList[i]
        while added:
            added = False
            newQi = set()
            for obj in Qi:
                if obj.isComplete():
                    c  = obj.mVariable
                    j  = obj.mIndex
                    Qj = self.mStateList[j]
                    for waiting in Qj:
                        if waiting.sameVar(c):
                            moved = waiting.moveDot()
                            newQi.add(moved)
            if not (newQi <= Qi):
                change = True
                added  = True
                Qi |= newQi
        return change

    EarleyParser.complete = complete
    del complete

\\[0.2cm]
\hspace*{1.3cm}
$\pair(c \rightarrow \gamma \bullet, j) \in Q_i \wedge
 \pair(a \rightarrow \beta \bullet c \delta,k) \in Q_j \;\Rightarrow\;
 Q_i := Q_i \cup \bigl\{ \pair(a \rightarrow \beta c \bullet \delta,k) \bigr\}$.
\begin{enumerate}
\item Line 2 initializes the variable \texttt{change} to \texttt{False}.  This variable records whether the method
      has added at least one Earley object to $Q_i$.  It is the result of the method, which is returned in line 21.
\item Line 3 initializes the variable \texttt{added} to \texttt{True} so that the \texttt{while} loop in line
      5 -- 20 is entered.  This loop is repeated as long as its last iteration has added a new Earley object to
      $Q_i$, since a new Earley object can be complete, too, and then it might enable further completions.
\item Line 4 sets the variable \texttt{Qi} to the set $Q_i$.
\item At the beginning of every iteration, line 6 resets \texttt{added} to \texttt{False} and line 7 creates the
      empty set \texttt{newQi}, which collects the Earley objects found in this iteration.  These Earley objects
      cannot be added to $Q_i$ immediately, since \textsl{Python} does not allow a set to be changed while a loop
      iterates over this set.
\item The \texttt{for} loop in line 8 -- 16 inspects all Earley objects in $Q_i$.  Line 9 selects the complete Earley
      objects, which have the form $\pair(c \rightarrow \gamma \bullet, j)$.  Line 10 and 11 extract the variable
      $c$ and the index $j$ from such an Earley object and line 12 sets the variable \texttt{Qj} to the set $Q_j$.
\item The \texttt{for} loop in line 13 -- 16 inspects all Earley objects in $Q_j$.  Line 14 selects those Earley
      objects that have the form $\pair(a \rightarrow \beta \bullet c \delta, k)$.  For each of them, line 15 moves
      the marker over the variable $c$, which results in the Earley object
      $\pair(a \rightarrow \beta c \bullet \delta, k)$, and line 16 adds this Earley object to \texttt{newQi}.
\item Line 17 checks whether the set \texttt{newQi} contains an Earley object that is not yet an element of $Q_i$.
      Here, the operator \texttt{<=} tests whether its left operand is a subset of its right operand.  If a new Earley
      object has been found, line 18 and 19 record this fact and line 20 adds the new Earley objects to the set
      \texttt{Qi}.  The operator \texttt{|=} changes this set in place.  As line 4 has not copied the set $Q_i$ but
      has only given it a second name, line 20 also enlarges the set \texttt{self.mStateList[$i$]}.
\end{enumerate}

    def predict(self, i):
        change = False
        added  = True
        Qi     = self.mStateList[i]
        while added:
            added = False
            newQi = set()
            for obj in Qi:
                c = obj.nextVar()
                if c is not None:
                    for rule in self.mGrammar.mRules:
                        if c == rule[0]:
                            newQi.add(EarleyObject(
                                c, (), tuple(rule[1:]), i))
            if not (newQi <= Qi):
                change = True
                added  = True
                Qi |= newQi
        return change

    EarleyParser.predict = predict
    del predict

\hspace*{1.3cm}

 \wedge (c \rightarrow \gamma) \in R
 \;\Rightarrow\;
 Q_i := Q_i \cup\bigl\{ \pair(c \rightarrow \bullet\gamma, i)\bigr\}$.

\begin{enumerate}
\item Line 2 -- 7 agree with the lines 2 -- 7 of the method \texttt{complete}.
\item The \texttt{for} loop in line 8 -- 14 inspects all Earley objects in $Q_i$.  Line 9 computes the variable
      following the marker.  If there is such a variable, the Earley object has the form
      $\pair(a \rightarrow \beta \bullet c \delta, k)$ and the test in line 10 succeeds.
\item The \texttt{for} loop in line 11 -- 14 inspects all grammar rules.  Line 12 selects those rules that have
      the variable $c$ on their left hand side.  For every such rule $c \rightarrow \gamma$, line 13 -- 14 add the

      the symbols of the right hand side $\gamma$.  It has to be converted into a tuple, since the methods of the

\item Line 15 -- 18 agree with the lines 17 -- 20 of the method \texttt{complete}.  The iteration is needed here,

        Qi = self.mStateList[i]
        n  = len(self.mString) - 1 # mString[0] = None
        if i + 1 <= n:
            T = self.mString[i+1]
            for obj in Qi:

\\[0.2cm]
\hspace*{1.3cm}
$\pair(a \rightarrow \beta \bullet T \gamma, k) \in Q_i \wedge x_{i+1} = T
 \;\Rightarrow\;
 Q_{i+1} := Q_{i+1} \cup \bigl\{ \pair(a \rightarrow \beta T \bullet \gamma, k) \bigr\}$.
\begin{enumerate}
\item Line 2 sets the variable \texttt{Qi} to the set $Q_i$ and line 3 computes the number $n$ of tokens.
\item The test in line 4 is necessary because the set $Q_n$ has no successor:  If $i = n$, then all tokens have
      been read and there is nothing left to do.
\item Line 5 sets the variable \texttt{T} to the next token $x_{i+1}$.
\item The \texttt{for} loop in line 6 -- 8 inspects all Earley objects in $Q_i$.  Line 7 uses the method

      marker, i.e.~those that have the form $\pair(a \rightarrow \beta \bullet T \gamma, k)$ where $T = x_{i+1}$.

\end{enumerate}
In contrast to the methods \texttt{complete} and \texttt{predict}, no iteration is necessary here and the new Earley
objects can be added directly, since they are added to the set $Q_{i+1}$ and not to the set $Q_i$.
